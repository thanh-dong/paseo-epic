# paseo-epic Runs the Flow Only: Implementation Plan

> **For agentic workers:** Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The plugin runs the flow (init, start, close, next, status, spawn), the git and PR mechanics, the flow guards, and the context preparation. It checks no ids and no file content.

**Architecture:** Ids become opaque strings. The epic id is the folder name before the first `-`; a story id is the first word of a story-list row. The next story is the `HANDOFF.md` header `next=`; the last closed story is `after=`. The lint (`checkPackage`, `closeProblems`, `renderStatus`) and the two lint tools go. `.epic.yml` gains `hooks.init` and `epicBranchPrefix`.

**Tech Stack:** TypeScript, `@getpaseo/plugin` 0.10.2, zod 4, vitest 4, git and `gh` as child processes.

**Spec:** `docs/superpowers/specs/2026-10-20-flow-only-design.md`

**Branch:** `feat/flow-only` in `/Volumes/ExDrive/_sources/paseo-epic-flow-only` (worktree, cut from `origin/main` `bd28325`).

## Global Constraints

- Every refusal is one `EpicError` sentence that names what the flow needs.
- No new RPC, no new config beyond `hooks.init` and `epicBranchPrefix`.
- `<!-- -->` blocks are skipped when rows and ledger entries are read.
- `npm run build:mcp` after source changes; `mcp/epic-mcp.mjs` and `server/mcp/bundle.generated.ts` are committed with the change they belong to (the MCP test rebuilds them on every run).
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Decisions (spec gaps)

1. **`epic_init` refuses an epic id that is empty or holds `-`, `/`, `\` or whitespace.** The id is the folder name before the first `-`, so such an id makes the package impossible to find. This is a flow need, not an id shape.
2. **`statusDir` "not closed" = the local handoff `next=` is not `none`.** The spec defines closed once: `next=none`. The Status block stays display only.
3. ~~The client close prompt passes no hooks.~~ Changed after code review: the status result carries `closeHooks` (from `hooks.close`) and the client's `/epic close` prompt quotes them. No new RPC; one new field in the status contract.
4. **Agent-facing `/epic start <story>` text becomes the `epic_start` tool sentence.** `nextPrompt`'s first line, `afterNext` with no agent, the "workspace exists" spawn message and the two spawn-hook fallbacks. The `/epic` slash command stays in the client; only its `check` verb goes.
5. **"Newest package" uses a natural sort of the epic id** (`E9` < `E10`, any shape), not `Number(id.slice(1))`.
6. **The story-list header row is the row right before the `---` separator**, so a header that is not `Story` is not read as a story.
7. **`cmdInit` writes the computed epic branch into the template's `epic/ENN-slug`** before the `ENN-slug` pass, so the Status block `Branch:` line shows the real branch with any `epicBranchPrefix`.

### Added after code review (PR #7)

8. **`epic_close` refuses unless the local handoff says `after=<story>`, and when it still says `next=<story>`.** The plugin reads both fields itself (`next` reads `after=`, `start` reads `next=`), so they are flow state, not content. Checked before any write.
9. **Comments are stripped as spans, not lines.** Every `<!--…-->` span (several per line, or across lines) is removed from the whole file first; then the Story list and the Ledger are cut from the stripped lines. An unclosed `<!--` strips to the end of the file, as markdown renders it. The line breaks inside a span are kept, so `Row.lineNo` still points at the real line.
10. **`epic_next` names a later closed story.** When the tip's `after=` is a story whose row comes after the asked story, it says "`<story>` is not the last closed story …; … so run next `<after>`". Otherwise it keeps "not merged … yet".
11. **One helper, `storyOfName(ids, prefix, name)`, picks the longest id `name` starts with as `<prefix><id>-`.** Used by the close branch guard, `pickMergedPr`, `statusDir`, `packetSlug` and `story-changes.ts`, so rows `S` and `S-1` never collide.
12. **`statusDir` checks the exact epic-branch match across all packages first**, then the story-branch match.
13. **`findEpicDir` refuses a ref with `/`, `\` or `..`** before the folder-name fallback.

## Review Focus

1. A commented `### TH-NNN — YYYY-MM-DD` under `## Ledger` is never returned as the ledger entry, and a comment block after a real entry is not copied into the PR body.
2. `epic_start` with a story that is not the tip's `next=` still refuses; `epic_next` with a story that is not the tip's `after=` still refuses.
3. Every flow guard keeps its refusal test: dirty tree, epic branch not pushed, open story PR (gh path covered by text only), wrong branch at close, stray changes at close, not merged at next.
